Quick start

Evaluate your algorithm under a shifted environment.

RobustRLlib is installed from a source checkout and used from the root of the checkout. The tutorial quick start runs these steps with their outputs.

1Install

# Python 3.8 or newer; the documentation was run with 3.11
conda create -n robustrllib python=3.11 && conda activate robustrllib
pip install -e ".[mujoco]"
pip install -r requirements.txt
pip install pyyaml torch minari

2Create a shifted environment

from robustrllib import make_robust, ShiftSpec

# A deployment condition is an ordered list of shifts; the list order is the stacking order.
env = make_robust("Hopper-v5", shifts=[
    ShiftSpec("dynamics", "scale", {"param": "gravity", "factor": 1.3}),  # Dynamic shift
    ShiftSpec("observation", "gauss", {"sigma": 0.05}),                 # Observation shift
], seed=0)

obs, info = env.reset(seed=0)
obs, reward, terminated, truncated, info = env.step(env.action_space.sample())
print(round(env.unwrapped.model.opt.gravity[2], 3))
-12.753

3Train a method and evaluate it under shift

# One experiment card names an algorithm, a task and an evaluation grid.
python baselines/train.py -c robustrllib/configs/experiment/rorl_hopper.yaml --seed 0

# The frozen checkpoint is scored on every condition of the grid: 20 paired episodes per
# condition, the same episodes for every method, unclipped normalized score.
python baselines/evaluate.py --run runs/rorl_hopper/seed0

Shift toolbox

Six shift sources, five modes, six task families.

A shift has a source, which says what is perturbed, and a mode, which says how the intervention is built: stochastic, adversarial, parametric, non-stationary through a schedule, or a composition of several shifts. A shifted environment is a base task with one wrapper per shift; the task code is not modified.

Results

A capability map of robust RL algorithms.

Every number comes from the same protocol: the frozen checkpoint of each method, 20 paired episodes per condition, five training seeds, and the normalized score in which 0 is a random policy and 100 the reference policy, unclipped. Shift magnitudes are grouped into quartiles Q1–Q4 by displacement from the nominal setting.

Findings

  • Robust RL helps at every magnitude, but both standard and robust methods degrade as shifts intensify.
  • Dynamics-aware mechanisms are stronger under dynamics shifts; online robust methods gain most over their base algorithms.
  • Claimed channels do not fully predict empirical strengths: a method's strongest shift source is often not the one it was designed for.
  • Under compound shifts the dynamics factor costs the most on both tasks, while the next most damaging source differs by task.
  • On the robotic tasks, robustness transfers return but not constraint satisfaction, and the semantic shift affects the VLA policy most.
